# 훈련일지 → Hugo 포스트 자동 생성

입력: 사용자가 붙여넣은 훈련일지 원문 텍스트 + (선택) 썸네일 이미지, 본문 이미지 파일 경로.
출력: `content/post/training_YYYYMMDD/` 페이지 번들 (index.md + 이미지).

## 1. 입력 해석

원문에서 다음을 추출한다. 확실하지 않은 값은 추측하지 말고 사용자에게 묻는다.

- **날짜**: 원문에 적힌 훈련 날짜 (YYYY-MM-DD). 연도가 없으면 오늘 기준 가장 가까운 과거 날짜로 보고 사용자에게 확인.
- **훈련 구분(categories)**: `코칭훈련` 또는 `자체훈련`. 원문에 코치/코칭 언급이 있으면 코칭훈련, 아니면 사용자에게 확인.
- **세트 구성**: 웜업, 드릴, 메인, 스타트, 쿨다운 등 각 항목의 거리 × 개수, 인터벌(사이클), 장비(핀/맨발 등), 강도, 코칭 포인트.
- **이미지**: 사용자가 이미지를 주면 어떤 것이 썸네일인지 확인한다(하나뿐이면 썸네일로 사용). 이미지가 없으면 이미지 관련 항목은 모두 생략.

원문에 없는 내용(거리 합계 제외)을 지어내지 않는다. 총 거리는 각 세트를 직접 계산하고, 원문 합계와 다르면 사용자에게 알린다.

## 2. 폴더/파일 생성

- 경로: `content/post/training_YYYYMMDD/index.md`
- 이미 같은 폴더가 있으면 덮어쓰지 말고 사용자에게 확인한다. (같은 날 두 번째 글이면 `training_YYYYMMDD_2` 등 제안)
- 이미지가 있으면 같은 폴더에 복사한다. 파일명은 `YYYY-MM-DD-01.jpeg`, `YYYY-MM-DD-02.jpeg` … 형식 (원본 확장자 유지, 썸네일이 01).

## 3. index.md 형식

기존 포스트(`content/post/training_20260927/index.md`, `content/post/training_20260913/index.md`)의 형식을 따른다. 작성 전 가장 최근 training 포스트 하나를 읽어 최신 스타일을 확인한다.

```markdown
---
title: YYYY-MM-DD 자체훈련
date: YYYY-MM-DD
description: 핵심 훈련 내용 한 줄 요약
image: YYYY-MM-DD-01.jpeg      # 썸네일이 있을 때만
tags:
  - 영법/주요 키워드 3~6개 (예: 자유형, 메인셋, 인터벌, 드릴, 핀수영)
categories:
  - 자체훈련
---

# 🏊‍♂️ 자체훈련 (YYYY-MM-DD)

---

### 📊 훈련 요약표

| 구분 | 훈련 항목 | 상세 구성 | 총 거리 / 시간 | 주요 내용 / 사이클 |
| :--- | :--- | :--- | :--- | :--- |
| **1. WARM-UP** | ... | ... | 400m | ... |
| **합계** | **총 훈련 거리** | | **2,100m** | |

---

### 📝 세부 훈련 내용

#### 1. WARM-UP (웜업) — 400m
* **항목:** 200m
* 인터벌은 `@ 1′50″` 처럼 인라인 코드로 표기

---

#### 2. ...
```

규칙:
- 섹션 사이에는 `---` 구분선.
- 장비 정보가 있으면 요약표에 `장비` 열을 추가한다(training_20260913 참고).
- 코칭 포인트·주의사항은 `💡`, `⚠️` 와 굵게 표시로 강조.
- 본문 이미지는 해당 섹션 아래에 `![](YYYY-MM-DD-02.jpeg)` 로 삽입. 썸네일은 front matter `image:` 로만 사용.
- 표 셀 안 줄바꿈은 `<br>` 사용 가능 (markup.toml 에 `unsafe = true`).

## 4. 확인 및 마무리

1. 생성한 파일 경로와 요약(날짜, 구분, 총 거리, 이미지 개수)을 보여준다.
2. `hugo` 가 설치되어 있으면 `hugo --gc --quiet` 로 빌드 에러가 없는지 확인한다. 없으면 생략했다고 알린다.
3. 사용자가 원하면 커밋한다. 커밋 메시지 형식: `feat: YYYY-MM-DD 자체훈련` (기존 커밋과 동일).
4. `main` 에 push 하면 GitHub Actions 가 바로 사이트에 배포하므로, push 는 사용자가 명시적으로 요청했을 때만 한다.
